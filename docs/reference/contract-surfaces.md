# Contract Surfaces

Registry of load-bearing names — types, functions, routes, and schema fields that
multiple changes depend on. When you rename or change the shape of anything here,
update every consumer and this entry. One row per surface.

## Card data (roadmap F-01 · `card-data-resolution`)

| Surface            | Kind     | Location                        | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------ | -------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Card`             | type     | `src/lib/card-data/types.ts`    | A resolved card: `name`, `typeLine`, `category`, `imageUrl`, `priceUsd`, `priceEur`. Consumed by S-01 (grouping), S-02 (images), S-03 (prices).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `CardCategory`     | type     | `src/lib/card-data/types.ts`    | The 7 grouping buckets (`land`/`creature`/`instant`/`sorcery`/`artifact`/`enchantment`/`planeswalker`) plus `other`. S-01 groups by this.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `UnresolvedCard`   | type     | `src/lib/card-data/types.ts`    | An input name that did not resolve: `name`, `reason` (`not-found`/`ambiguous`/`malformed`), `suggestion`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `ResolutionResult` | type     | `src/lib/card-data/types.ts`    | Partial-success return shape: `{ resolved: Card[]; unresolved: UnresolvedCard[]; matched: ReadonlyMap<string, Card> }`. **`matched` to join by input, `resolved` to render.** `matched` maps the _caller's_ `resolutionKey(inputName)` to the card it produced — not derivable from `resolved`, because the source matches names more forgivingly than `resolutionKey` (front face + lowercase) and answers "Jace the Mind Sculptor" with the differently-keyed "Jace, the Mind Sculptor". Deliberately partial: absent when the association is ambiguous, so `matched.size <= resolved.length` and every key is one the caller passed. _(`matched` added in `testing-derive-to-persist`.)_ |
| `classifyType`     | function | `src/lib/card-data/classify.ts` | `(typeLine: string) => CardCategory`. Deterministic precedence over overlapping types.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `resolveCards`     | function | `src/lib/card-data/resolve.ts`  | `(names: string[]) => Promise<ResolutionResult>`. Public resolver via the card-data source. Attributes returned cards to the inputs that fetched them (`ResolutionResult.matched`) by exact key first, then a **sole-residual** pair only — two or more ambiguous cards in one batch record nothing rather than rest on response ordering. _(Implemented in F-01 Phase 2; attribution added in `testing-derive-to-persist`.)_                                                                                                                                                                                                                                                               |
| `resolutionKey`    | function | `src/lib/card-data/resolve.ts`  | `(name: string) => string`. Front-face identity key (lowercased). Shared by the resolver's dedup/cache **and** the deck-layer quantity join so a card's front-only and full `// ` forms collapse to one key. _(Extracted in `deck-diff-quantities`.)_                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `quantifyResolved` | function | `src/lib/card-data/resolve.ts`  | `(resolution, quantityByInputKey) => Map<string, number>`. The **shared** count join: totals each resolved card's copies from the caller's per-input counts, keyed out by canonical `resolutionKey`. Both add flows (`attachQuantities` and `deriveSnapshot`) route through it so their fallback chain cannot drift — `matched` sum, else canonical-key lookup, else 1. _(Added in `testing-derive-to-persist`.)_                                                                                                                                                                                                                                                                           |

> Module entry point: import these from `@/lib/card-data`.

## Deck diff (roadmap S-01 · `grouped-upgrade-plan`)

| Surface                | Kind     | Location                   | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | -------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `parseDeckList`        | function | `src/lib/deck/parse.ts`    | `(text: string) => ParsedDeck`. Tolerant deck-list parser: drops blanks/comments/section headers, extracts `{name, quantity}` entries, collects unreadable lines as `malformed`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `diffDecks`            | function | `src/lib/deck/diff.ts`     | `(base: DeckCard[], target: DeckCard[]) => UpgradePlan`. Quantity-aware per canonical `Card.name`: `shared = min`, `remove`/`add` = the delta (a partly-changed card appears in both). Each partition grouped by `category` in `CATEGORY_ORDER`; empty / zero-quantity buckets omitted.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `UpgradePlan`          | type     | `src/lib/deck/diff.ts`     | The computed plan: `{ remove, add, shared }`, each a `CardGroup[]`. Enriched by S-02 (images) / S-03 (prices) on the same shape.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `CardGroup`            | type     | `src/lib/deck/diff.ts`     | One category's cards: `{ category: CardCategory; cards: DeckCard[] }`. The render unit for a typed subsection.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `DeckCard`             | type     | `src/lib/deck/diff.ts`     | A card paired with a copy count: `{ card: Card; quantity: number }`. The deck-layer holding / diff-delta unit — keeps quantity off the pure `Card` identity. _(Added in `deck-diff-quantities`.)_                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `generateUpgradePlan`  | function | `src/lib/deck/plan.ts`     | `(baseText, targetText) => Promise<PlanOutcome>`. Parses both texts first to short-circuit `empty` before any lookup fires, then orchestrates `resolveDeck` ×2 (sequential, warming the resolver's in-session cache) → `diffDecks`; returns `ok` / `empty` / `error`, with deck-tagged `unresolved` entries. _(Interior moved behind `resolveDeck` in `diff-style-checkpoint-entry`.)_                                                                                                                                                                                                                                                                                                                                                      |
| `resolveDeck`          | function | `src/lib/deck/plan.ts`     | `(text: string) => Promise<ResolvedDeck>`. One deck's whole read path: `parseDeckList` → `resolveCards` → `attachQuantities`, merging the parser's malformed lines (first) with the resolver's misses (second) into one untagged `unresolved` list. Throws only on a transient resolver transport failure — unknown _names_ never throw. Imported from `@/lib/deck`. _(Extracted in `diff-style-checkpoint-entry`.)_                                                                                                                                                                                                                                                                                                                        |
| `ResolvedDeck`         | type     | `src/lib/deck/plan.ts`     | `{ deck: DeckCard[]; unresolved: UnresolvedCard[] }`. One deck's resolution — quantity-tagged cards plus every input that did not become a card. A caller comparing two decks tags each entry with a `DeckSide`. Imported from `@/lib/deck`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `attachQuantities`     | function | `src/lib/deck/quantity.ts` | `(resolution: ResolutionResult, entries: DeckEntry[]) => DeckCard[]`. Joins resolved cards to their parsed quantities, summing duplicate lines and merging DFC name forms by `resolutionKey` (fallback quantity 1). Takes the **whole resolution**, not its `resolved` array, so the cards and their input association cannot be passed separately and drift — the join runs through `matched` via `quantifyResolved`. _(Added in `deck-diff-quantities`; signature changed in `testing-derive-to-persist`.)_                                                                                                                                                                                                                               |
| `splitCardLine`        | function | `src/lib/deck/parse.ts`    | `(line: string) => { prefix: string; name: string } \| null`. The single "is this a card line, and where does the name start" rule: `null` for blank/comment/header/count-only lines, else the verbatim count prefix + trimmed name. Three consumers: `parseDeckList`, `applySuggestion`, and — **cross-module** — `src/lib/path/delta.ts`, which strips a `+`/`-` sign and delegates the remainder so diff-mode and full-paste lines split by exactly one rule. Not on the `@/lib/deck` barrel, but the path layer imports it by deep path (`@/lib/deck/parse`), so it is load-bearing across modules despite being off the public entry point. _(Added in `did-you-mean-accept`; third consumer added in `diff-style-checkpoint-entry`.)_ |
| `applySuggestion`      | function | `src/lib/deck/accept.ts`   | `(text, targetName, suggestion) => string`. Rewrites every deck-list line whose name matches `targetName` by `resolutionKey` to `<verbatim count prefix><suggestion>`, leaving non-card and non-matching lines verbatim. Imported from `@/lib/deck`. _(Added in `did-you-mean-accept`.)_                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `acceptAllSuggestions` | function | `src/lib/deck/accept.ts`   | `(baseText, targetText, entries: UnresolvedEntry[]) => { baseText, targetText }`. Folds `applySuggestion` over each deck's text for every entry with a non-null `suggestion`, routing by `entry.deck`. Imported from `@/lib/deck`. _(Added in `did-you-mean-accept`.)_                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

> Module entry point: import these from `@/lib/deck`. `splitCardLine` is the one exception — it is not on the barrel but **is** imported cross-module by `src/lib/path/delta.ts` via `@/lib/deck/parse`, so treat it as public in practice.

## API wire contract (test-plan §3 Phase 2 · `testing-api-contract-pinning`)

Everything that crosses the HTTP boundary. The **authority** for which status pairs with
which body is the decided-contract table in
`context/changes/testing-api-contract-pinning/plan.md` (each row marked `documented` or
`decided`); the types below make those shapes checkable and the suites in
`tests/integration/contract-*.int.test.ts` pin them. Changing a row here means changing
that table, the suites, and every consumer — see test-plan §6.3.

### Routes

Success-body **key sets are closed**: no extra keys, none missing, so an additive field is
a deliberate test edit rather than a silent pass.

| Route                          | Kind  | Location                            | Contract                                                                                                                                                                                                                                                                                        |
| ------------------------------ | ----- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/paths`               | route | `src/pages/api/paths/index.ts`      | `200` + bare `UpgradePath[]`, `created_at` **desc**. No application consumer — `/paths` renders `toPathWithSummary` server-side instead. Pinned, not deleted.                                                                                                                                   |
| `POST /api/paths`              | route | `src/pages/api/paths/index.ts`      | `PathTitleRequest` → `201` + `UpgradePath`. Missing/blank `title` → `400 {error: "Title is required"}`.                                                                                                                                                                                         |
| `GET /api/paths/[id]`          | route | `src/pages/api/paths/[id].ts`       | `200` + `PathWithStepsResponse` (`{path, steps}`), steps by `position` **asc**. No application consumer — `src/pages/paths/[id].astro` runs the same mappers and `.order()` clauses independently. `contract-page-agreement.int.test.ts` pins the two against each other.                       |
| `PATCH /api/paths/[id]`        | route | `src/pages/api/paths/[id].ts`       | `PathTitleRequest` → `200` + the **post-update** `UpgradePath`. A body is required, not optional: `PathEditor` reads `updated.title`. `204` is explicitly rejected.                                                                                                                             |
| `DELETE /api/paths/[id]`       | route | `src/pages/api/paths/[id].ts`       | `204`, empty body (steps cascade). No consumer reads a body.                                                                                                                                                                                                                                    |
| `POST /api/paths/[id]/steps`   | route | `src/pages/api/paths/[id]/steps.ts` | `StepCreateRequest` → `201` + `PathStep` carrying the **server-assigned** `position` (`max+1`, base 0). Malformed body → `400 {error: "Invalid step payload"}`, checked **before** ownership — so a bad body aimed at another owner's path answers 400, not 404. Deliberate; keep the ordering. |
| `DELETE /api/paths/[id]/steps` | route | `src/pages/api/paths/[id]/steps.ts` | Deletes only the highest-`position` step (delete-last invariant) → `204`, empty. No visible steps → `404 {error: "No steps to delete"}`. Never queries `upgrade_paths`, so a cross-owner call is answered by RLS alone and is indistinguishable from an empty own path.                         |
| `POST /api/auth/signin`        | route | `src/pages/api/auth/signin.ts`      | Form POST → `302` with `Location: /paths` and chunked `sb-*` `Set-Cookie` parts. The integration harness's own foundation — `tests/integration/helpers/owners.ts` reassembles the chunks — so this is load-bearing for every DB-backed suite. Failure stays on the `?error=` redirect channel.  |

Error bodies, every `/api/paths/*` route:

| Case                                        | Status | Body                                     |
| ------------------------------------------- | ------ | ---------------------------------------- |
| no session, or an invalid one               | `401`  | `{error: "Unauthorized"}`                |
| `[id]` absent, not owned, **or not a UUID** | `404`  | `{error: "Not found"}`                   |
| unexpected server failure                   | `500`  | `{error: "Internal error", ref: <uuid>}` |

**The `500` body is redacted on purpose.** A raw `PostgrestError.message` names tables,
columns and constraints. The cause is `console.error`'d against `ref`, which is the only
thing correlating a failed response to its log line — so any change to `serverError` must
keep `ref` on both ends, and the integration harness must keep piping the dev server's
stderr to the parent (`tests/integration/global-setup.ts`).

**Denial is `404`, never `403`.** RLS makes another owner's rows invisible, so a handler
cannot distinguish "absent" from "not yours."

| ----------------------- | -------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ApiError`              | type     | `src/lib/api/contract.ts` | `{error: string}` — every non-2xx body. | `ApiServerError`        | type     | `src/lib/api/contract.ts` | `ApiError & {ref: string}` — the `500` body. `ref` is the correlation handle, not decoration.                                                                                                                                                                                                                                                          |

| `StepCreateRequest`     | type     | `src/lib/api/contract.ts` | `{name, listText, snapshot, deltaText?}` — request body for `POST steps`. `position` is **server-owned** and ignored if sent. `deltaText` is optional on the request and collapses (non-string or blank → `null`); on the response it is **always present** as `string \| null`, never `undefined`. | `jsonResponse<T>`       | function | `src/lib/api/paths.ts`    | `(data: T, status = 200) => Response`. | `errorResponse`         | function | `src/lib/api/paths.ts`    | `(message, status) => Response`. The one place an `ApiError` body is built.                                                                                                                                                                                                                                                                            |
| `serverError`           | function | `src/lib/api/paths.ts`    | `(detail: unknown) => Response`. Logs `detail` against a fresh `ref`, returns the redacted `ApiServerError`. | `parsePathId`           | function | `src/lib/api/paths.ts`    | `(context) => string \| null`. The `[id]` guard: `null` when the param is absent **or not a canonical hyphenated UUID**, which handlers turn into the decided `404`. Without it a malformed id reached `.eq("id", …)` and surfaced as a `500` carrying Postgres text.                                                                                  |
| `requireUser`           | function | `src/lib/api/paths.ts`    | `(context) => {supabase, user} \| Response`. Cookie-bound client + signed-in user, or the `401`. | `toUpgradePath`         | function | `src/lib/api/paths.ts`    | `(row: PathRow) => UpgradePath`. snake_case row → camelCase domain type.                                                                                                                                                                                                                                                                               |
| `toPathStep`            | function | `src/lib/api/paths.ts`    | `(row: StepRow) => PathStep`. Same convention, plus `parseSnapshot` on the stored `jsonb`. **Bypassing this mapper is the #1 drift seam**: a raw row makes `deltaText` `undefined`, and `undefined !== null` renders a spurious diff badge that a page reload heals — it presents as a flake.                                                          |
| `toPathWithSummary`     | function | `src/lib/api/paths.ts`    | `(row, stepRows) => PathWithSummary`. The saved-decks grid shape — `{path, summary}` from stored snapshots only, no card-data lookups. Used by `src/pages/paths/index.astro`, **not** by any route; deliberately a different shape from `GET /api/paths`.                                                                                              |
| `PathWithSummary`       | type     | `src/lib/api/paths.ts`    | `{path: UpgradePath; summary: PathSummary}`. The grid row.                                                                                                                                                                                                                                                                                             |
| `requestJson<T>`        | function | `src/lib/api/client.ts`   | `(input, init?) => Promise<RequestResult<T>>`. The browser's one typed seam for `/api/*` JSON. Write `T` explicitly — it is the client-side half of the same gate. Never throws: failures are `{ok: false, kind: "http" \| "transport"}` variants. | `RequestResult<T>`      | type     | `src/lib/api/client.ts`   | `RequestSuccess<T> \| HttpFailure \| TransportFailure`. Discriminated on `ok`, then on `kind`. `HttpFailure.fromBody` says whether `error` came from the server's `ApiError` or is the generic fallback — a caller with its own phrasing should prefer the server's message only when it is `true`.                                                    |

**Two module boundaries hold this apart, and both are load-bearing:**

- `src/lib/api/contract.ts` is **types only** — no runtime imports, no server plumbing —
  so a browser island imports it as freely as a route handler.
- `src/lib/api/paths.ts` is **server-only** (it reaches for Supabase and `astro`).
  `src/lib/api/client.ts` is the browser's half: it imports `./contract` and nothing from
  `./paths`. A runtime import added to `contract.ts` breaks both.

**Mapping convention: the wire is camelCase, the DB is snake_case.** Every row crossing the
boundary goes through a `to*` mapper in `src/lib/api/paths.ts` — `owner_id` → `ownerId`,
`path_id` → `pathId`, `list_text` → `listText`, `delta_text` → `deltaText`,
`created_at`/`updated_at` → `createdAt`/`updatedAt`. A new column is not on the contract
until a mapper names it and `src/lib/api/contract.ts` (or a domain type it re-exports)
declares it. Returning a row directly is the drift this section exists to prevent.
